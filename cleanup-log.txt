This was leftover from the old pipeline — the new `transcriber.py` handles ffmpeg audio
chunking directly via subprocess. No code in the project imported or used AudioExtractor.
Updated both CLAUDE.md files to remove stale references.

**Left alone:**

- `conftest.py` defines a `project_root` fixture not currently used by tests, but it's a

## Category 4: Duplication

**Addressed:** Extracted duplicated episode ID parsing and fixtures path constant.

- **`parse_episode_id`**: Logic to split `motd_YYYY-YY_YYYY-MM-DD` into `(broadcast_date, season)`
  was duplicated between `__main__.py` (inline) and `pipeline.py` (`_parse_episode_id` private fn).
  Extracted as a public function in `downloader.py` (which owns the episode_id format via
  `_derive_episode_id`). Both `__main__.py` and `pipeline.py` now import from there.
- **`DEFAULT_FIXTURES_PATH`**: The path `data/fixtures/premier_league_2025_26.json` was hardcoded
  identically in `__main__.py` and `pipeline.py`. Extracted as a constant in `fixtures.py` (which
  owns fixture loading). Both consumers now import it.
- **Type annotation fix**: `_load_fixtures` and `_do_analyse` in `pipeline.py` had bare `list`
  return/param types — tightened to `list[Fixture]`.
- Added tests for `parse_episode_id` including a roundtrip test with `_derive_episode_id`.

**Left alone:**
- Transcript/analysis JSON loading (`model_validate_json(path.read_text())`) appears in both
  `__main__.py` and `pipeline.py` — this is a one-liner Pydantic pattern, not worth extracting.
- Fixtures loading flow differs between CLI (user-facing error messages) and pipeline
  (`PipelineError`) — the divergent error handling justifies the small repetition.

## Category 3: Inconsistent patterns

**Addressed:** Standardised subprocess error handling across all modules.

Each module that shells out to an external process (`ffmpeg`, `ffprobe`, `yt-dlp`, `claude`)
now follows the same pattern established by `downloader.py`: define a module-specific exception
class and wrap `CalledProcessError` at the call site.

- **`analyser.py`**: Added `AnalysisError`. Replaced `RuntimeError` and `ValueError` raises
  with `AnalysisError` for both subprocess failures and JSON parse failures.
- **`transcriber.py`**: Added `TranscriptionError`. Wrapped the two bare `subprocess.run(check=True)`
  calls (`ffmpeg` chunking + `ffprobe` duration) that previously let `CalledProcessError` bubble.
- **`downloader.py`**: Wrapped `json.loads(meta_result.stdout)` in a try/except so malformed
  yt-dlp output raises `DownloadError` instead of raw `JSONDecodeError`.
- **`__main__.py`**: CLI `transcribe` and `analyse` commands now catch `TranscriptionError` and
  `AnalysisError` respectively, matching how `download` already caught `DownloadError`.
- **Tests**: Updated `test_analyser.py` to assert `AnalysisError` instead of `RuntimeError`/`ValueError`.

**Left alone:**
- `pipeline.py` doesn't catch module errors — it lets them propagate through `_timed()`.
  This is intentional; the pipeline is an internal orchestrator, not a user-facing boundary.
- `publisher.py` uses bare `os.environ[]` KeyError for missing R2 credentials — this is a
  deployment-time config error, not a runtime boundary worth a custom exception.

## Category 6: Missing error handling

**Addressed:** Added error handling at system boundaries where external input is untrusted.

- **`transcriber.py`**: `_get_audio_duration` now catches `ValueError` when ffprobe returns
  non-numeric output (e.g. "N/A") and raises `TranscriptionError` with context. Previously
  `float()` would raise a bare `ValueError`.
- **`transcriber.py`**: `_chunk_audio` now raises `TranscriptionError` if ffmpeg produces zero
  audio chunks. Previously an empty file or invalid input would silently produce an empty
  transcript with no indication of failure.
- **`fixtures.py`**: `_parse_fixture` now catches `KeyError` on required fields (match_id, date,
  home_team, away_team) and raises `ValueError` with the missing field name and raw data.
  Previously a corrupt fixtures file would raise a bare `KeyError`.
- **`analyser.py`**: `_parse_response` now catches Pydantic `ValidationError` when Claude's
  response has valid JSON but doesn't match the expected schema, wrapping it in `AnalysisError`.
  Also validates that `matches` is actually a list. Previously `ValidationError` leaked through
  as an internal error.
- **`publisher.py`**: `publish` now catches `JSONDecodeError`/`TypeError` when reading a
  corrupted `index.json` from R2, logging a warning and rebuilding the index from scratch.
  Previously a corrupt index would crash the publish step.

**Left alone:**
- No subprocess timeouts added. All subprocesses are either fast (ffprobe) or inherently
  long-running (ffmpeg chunking, yt-dlp download, Claude analysis). Adding arbitrary timeouts
  would create false failures; the correct solution for hung processes is system-level monitoring.
- `pipeline.py` reading cached transcript/analysis JSON — a corrupt cache file raising
  `ValidationError` is a reasonable failure mode since the pipeline can be re-run with `--force`.
- `publisher.py` `os.environ[]` for R2 credentials — deployment-time config, not runtime input.

## Category 7: Test quality

**Addressed:** Improved test coverage at system boundaries and tightened assertions.

- **`test_downloader.py`**: Added `test_malformed_metadata_json_raises` — the `json.loads` error
  path on yt-dlp metadata (wrapped as `DownloadError` in category 3) had no test coverage.
- **`test_analyser.py`**: `test_analyse_returns_valid_analysis` previously only checked
  `len(analysis.matches) == 2` and verified the mock was called — it now asserts episode_id,
  broadcast_date, season, match order, and team names to verify end-to-end parsing.
- **`test_analyser.py`**: `test_prompt_formats_timestamps_as_mmss` (renamed) now asserts exact
  `[MM:SS]` format (`[00:00]`, `[00:10]`, `[01:00]`) instead of the loose
  `"00:00" in prompt or "0.0" in prompt` which would accept wrong formats.
- **`test_fixtures.py`**: `test_fixture_missing_required_field_raises` parametrised over all four
  required fields (`match_id`, `date`, `home_team`, `away_team`). Previously only tested `match_id`.
- **`test_transcriber.py`**: Added `test_chunk_audio_ffmpeg_failure_raises` — the
  `CalledProcessError` → `TranscriptionError` wrapping in `_chunk_audio` had no test.
- **`test_transcriber.py`**: Added `test_ffprobe_failure_raises` — the subprocess failure path
  in `_get_audio_duration` had no test.
- **`test_transcriber.py`**: Added `test_empty_chunk_produces_no_segments` — verifies the
  transcribe flow handles a silent chunk (empty segment list) without breaking.

**Left alone:**
- Pipeline tests are heavily mocked but this is appropriate for unit tests — the pipeline is
  an orchestrator and its value is in sequencing/caching logic, not data transformation.
- Publisher tests use a FakeR2Client rather than mocking boto3 — this is fine for unit tests;
  real S3 protocol verification belongs in integration tests against a local S3 endpoint.
- No integration tests added for cache corruption in pipeline — the current behaviour (Pydantic
  `ValidationError` propagates, user re-runs with `--force`) is acceptable and documented.

## Category 3 (continued): Inconsistent logging style

**Addressed:** Standardised logging format strings across all modules.

`downloader.py`, `publisher.py`, and `pipeline.py` used `%`-style formatting in logger calls
(deferred evaluation — string not constructed unless the log level is active). `analyser.py` and
`transcriber.py` used f-strings (eager evaluation). Converted all 7 f-string logger calls in
`analyser.py` (3) and `transcriber.py` (4) to `%`-style to match the rest of the codebase.

**Left alone:**
- Pre-existing ruff I001 (import sorting) warnings in `__main__.py` for deferred imports inside
  Click command functions — these are false positives since ruff doesn't understand that
  `from motd.transcriber import TranscriptionError, transcribe as do_transcribe` is a single
  logical import deferred for startup performance.

## Categories 2 (Security) and 5 (Shallow modules)

**Reviewed, no issues found.**

- **Security**: All subprocess calls use list-form arguments (no `shell=True`). No hardcoded
  secrets — R2 credentials loaded from environment variables (standard for CLI tools).
  No path traversal risks — episode_id format is validated, output paths from CLI are
  user-controlled (appropriate for a local CLI tool). No unsafe deserialisation.
- **Shallow modules**: All modules provide meaningful abstraction. The `_do_*()` wrappers in
  `pipeline.py` exist to support deferred imports (avoids importing heavyweight deps like
  `openai`/`boto3` at module load time) — this is a legitimate pattern, not needless wrapping.

## Category 1 (continued): Dead code + Category 6 (continued): Missing error handling

**Addressed:**

- **`__main__.py`**: Removed unused `logger = logging.getLogger(__name__)`. The `logging` import
  itself is still needed for `logging.basicConfig()` in `cli()`, but the module-level logger was
  never referenced — all error output uses `click.echo()` (appropriate for a CLI boundary).
- **`fixtures.py`**: `_parse_fixture` wrapped `raw_score["home"]` / `raw_score["away"]` access
  in try/except for `KeyError` and `TypeError`. The previous error handling pass (Category 6)
  added validation for the 4 required top-level fields but missed the `final_score` sub-dict.
  A malformed score (missing keys, or `final_score` set to a non-dict like a string) now raises
  `ValueError` with context, matching the pattern used for top-level fields.
- **`test_fixtures.py`**: Added `test_fixture_malformed_score_raises` parametrised over 3 cases:
  missing "away", missing "home", and wrong type ("not-a-dict"). Covers both `KeyError` and
  `TypeError` paths.

**Left alone:**
- `conftest.py` `project_root` fixture — unused but a reasonable shared fixture to keep.
- `pipeline.py` `_timed()` has `# type: ignore[no-untyped-def]` — properly typing this with
  generics adds complexity for no runtime benefit; the function is private and small.
